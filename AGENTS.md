# AGENTS.md — AI Atlas

Operational guide for any coding agent working in this repo. Read this first, then
`CONTENT-PLAN.md` (progress + per-branch note outlines) and `SOURCES.md` (curated
authoritative sources to cite).

## What this is

**AI Atlas**: a static, framework-free, **bilingual** (EN canonical + ES overlay)
personal knowledge atlas about AI. Sibling of `cibersecurity-notes` (same
architecture, different visual identity). Plain-Python build, deployed to GitHub Pages.

## Build, run, verify

```bash
python3 build.py                                   # no deps required
python3 -m http.server 8011 --directory site       # → http://127.0.0.1:8011/en/
```

- The build prints a summary ending in `(unresolved links: N)`. **N must be 0.**
- After any content change, verify:
  ```bash
  python3 build.py
  grep -rl 'class="unresolved-link"' site/en site/es | wc -l   # must print 0
  ```
- `build.py` deletes and regenerates `site/` on every run. Never hand-edit `site/`.
- `python3 -m py_compile build.py` after editing `build.py`.

## Repo layout

```
content/en/ai/<branch>/<slug>.md   # canonical English notes (source of truth)
content/en/ai/<branch>/index.md    # branch landing: links its notes + "Core sources"
content/es/ai/<branch>/<slug>.md   # Spanish overlay (same path); missing → EN + banner
build.py                           # generator; BRANCHES dict = taxonomy/labels/accents/icons
static/assets/atlas.css|search.js  # design system + client search
static/*.svg|*.png                 # brand assets (PNGs generated by scripts/rasterize-brand-assets.sh)
site/                              # generated output — do not edit
CONTENT-PLAN.md                    # SOURCE OF TRUTH: progress checklist + per-branch outlines
SOURCES.md                         # curated authoritative sources per branch
```

## Taxonomy

12 knowledge branches + `ai-playbooks`, grouped into phases (see `CONTENT-PLAN.md`).
Branch config (label / group / accent / icon) lives in the `BRANCHES` dict in
`build.py`; Spanish labels in `BRANCHES_ES`. The phase a branch belongs to is its
`group`, which must match a key in `PHASES`. `build.py`'s `validate_taxonomy()` warns
on drift.

## How to write a note (match the bar — study `content/en/ai/foundations/*`)

Frontmatter:
```yaml
---
title: "Note title"
description: One-line SEO/search description.
tags: [tag-a, tag-b]
order: 4              # position within the branch (index is order 0)
updated: 2026-06-07
# featured: true      # at most ONE note across the whole atlas
# draft: true         # stage WIP; excluded from build/search/sitemap
---
```

Body shape (≈40–80 lines, dense, concrete, **no marketing**):
- `#` H1 = the title.
- 1–2 sentence framing of why the concept matters.
- 2–4 `##` sections using bullets and/or tables.
- A **Pitfall** or **In practice** angle.
- Close with `**Connects to:**` + a line of `[[wikilinks]]`.

Links: `[[ai/<branch>/<slug>|Label]]` (path form) or `[[slug|Label]]`. Anchors:
`[[ai/x/y#heading|Label]]`. **Never leave an unresolved link** — only link to notes /
indexes that already exist. Add the new notes' `[[links]]` to the branch `index.md`.

Sources: each branch `index.md` ends with `## Core sources` listing 3–5 real,
authoritative sources pulled from `SOURCES.md`.

## Renderer gotcha (important)

`markdown` is usually **not** pip-installed locally, so `build.py` falls back to its
built-in renderer. **Author for the fallback:** use ATX headings, **flat** (non-nested)
bullet/numbered lists, tables, blockquotes, fenced code, and inline
code/bold/italic/links. Avoid nested lists and exotic Markdown. (CI installs
`markdown`+`pygments`, so production is richer — but if it renders in the fallback it
renders everywhere.)

## Conventions & constraints

- **EN-first.** ES overlays are a later pass. ES = **Rioplatense voseo** (usá, tenés,
  podés, hacé), technical and concise, mirroring EN density. Same path under
  `content/es/`.
- **One branch = 10–15 rich notes.** When a branch is done, tick it in
  `CONTENT-PLAN.md`.
- After each branch: build, confirm **0 unresolved links**, spot-check one page in the
  browser.
- **Do not commit unless the user explicitly asks.** Branch first if on `main`.
- Keep notes model-agnostic where the topic is; cross-link generously between branches
  (the value is the graph).

## Deploy

GitHub Pages via `.github/workflows/deploy.yml` (repo Settings → Pages → Source =
**GitHub Actions**). CI runs `python build.py` with `SITE_URL` = the Pages base URL and
uploads `site/`. Live at **https://ldamoredev.github.io/ai-notes/**. `site/` does not
need to be committed once CI is enabled.
